# Руководство по стилю документации

Документация сервиса бронирования ресторанов должна помогать читателю выполнить задачу с первого раза. Это руководство задаёт общие правила для пользовательских сценариев, REST API, конфигурации сервисов и действий при сбоях.

!!! abstract "Назначение руководства"

    Используйте его при создании и review страниц. Каждое правило объясняет, что проверить перед публикацией, и опирается на реальные сценарии сервиса.

## Начните с задачи читателя

Перед созданием страницы ответьте на три вопроса:

1. Кто будет читать документ: пользователь, интегратор или участник команды?
2. Какой результат он должен получить после прочтения?
3. Какие условия, данные и права нужны до первого шага?

## Короткий чек-лист перед Pull Request

- Документ отвечает на одну задачу читателя.
- Факты, команды и примеры проверены на рабочем сценарии.
- Для каждой сущности использовано название из глоссария.
- Изменение продукта сопровождается проверкой связанных страниц.
- Страница проходит Markdown lint и строгую сборку MkDocs.

## Как внести изменение

Создайте отдельную ветку, обновите правило и связанный пример, выполните проверки и откройте Pull Request. Подробный процесс описан в [CONTRIBUTING.md](https://github.com/Ezhidzee/style-guide-project/blob/main/CONTRIBUTING.md).
