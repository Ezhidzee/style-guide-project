# Доступность текста

Доступная документация помогает читателю получить информацию с помощью клавиатуры, программы чтения с экрана или мобильного устройства. Эти правила применяются к каждой новой и изменённой странице.

## Структура и язык

- Используйте последовательную иерархию заголовков. Не начинайте подраздел с заголовка третьего уровня после первого.
- Формулируйте заголовок так, чтобы он сообщал тему раздела. Заголовок «Ошибки создания бронирования» понятнее, чем «Важно».
- Объясняйте незнакомые сокращения при первом упоминании и делите длинную инструкцию на короткие шаги.

## Ссылки и элементы интерфейса

- Пишите описательный текст ссылки. Вместо «нажмите [здесь](technical.md)» используйте «откройте [правила описания API](technical.md)».
- Называйте кнопку, поле или вкладку по видимой подписи. Не объясняйте действие только цветом, положением или иконкой.
- Не передавайте состояние только цветом. Сообщение об ошибке дополняйте текстом и понятной рекомендацией.

## Изображения и мультимедиа

- У информативного изображения указывайте alt-текст, передающий его смысл. Например: `![Схема создания бронирования: запрос, проверка столика, подтверждение](images/booking-flow.png)`.
- Для декоративного изображения используйте пустой alt-текст:

  ```markdown
  ![](images/divider.png)
  ```

- Для видео и аудио добавляйте текстовое описание или расшифровку. Не размещайте важный фрагмент кода только на скриншоте.

## Проверка страницы

Перед публикацией проверьте, что страницу можно прочитать при ширине 320 CSS-пикселей и масштабе 200 %. Убедитесь, что все интерактивные элементы доступны с клавиатуры, ссылки различимы вне контекста, а таблицы имеют заголовки столбцов.
