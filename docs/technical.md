# Техническая документация

!!! danger "Не публикуйте секреты"

    В примерах используйте только тестовые адреса, идентификаторы и маркеры токенов. Перед публикацией проверьте фрагменты конфигурации и логи отдельно.

## Примеры запросов и ответов

Указывайте язык блока кода и оставляйте в примере только поля, необходимые для сценария. Идентификаторы, адреса и токены должны быть учебными. Для времени бронирования используйте ISO 8601 с часовым поясом.

```http
POST /api/v1/bookings
Content-Type: application/json
Authorization: Bearer <access_token>
```

```json
{
  "restaurant_id": "rest_123",
  "guests": 2,
  "starts_at": "2026-10-16T19:00:00+03:00"
}
```

## Конфигурация

Для каждой переменной окружения укажите назначение, формат, обязательность и безопасный пример значения. Никогда не публикуйте реальное содержимое `.env` и не копируйте секреты в примеры.

## Коды ошибок

Группируйте ошибки по действию пользователя или интегратора. Для каждой ошибки укажите код, условие возникновения и действие для исправления. Не ограничивайтесь текстом ошибки без объяснения следующего шага.

| Код | Когда возникает | Что сделать |
| --- | --- | --- |
| `409 Conflict` | На выбранное время нет свободного столика | Предложить читателю выбрать другое время или ресторан. |
| `422 Unprocessable Entity` | Значение поля не прошло проверку | Указать поле и допустимый формат значения. |

## Логи и персональные данные

Не добавляйте в примеры логов телефоны, адреса электронной почты, полные имена, платёжные данные и токены. Если такие поля нужны для объяснения формата, заменяйте их безопасными маркерами, например `<customer_email>`.
