# Markdown и оформление

!!! tip "Проверка перед публикацией"

    Убедитесь, что заголовки не пропускают уровни, ссылки понятны без контекста, а команды, имена файлов и значения параметров выделены inline code.

## Markdown

- Отделяйте заголовки, списки и блоки кода пустыми строками.
- Используйте дефис для маркированных списков и нумерованный список для шагов, которые выполняются в заданном порядке.
- Оформляйте команды, файлы, значения параметров и идентификаторы как inline code: `docker compose up -d`, `mkdocs.yml`, `booking_id`.
- Для многострочного примера используйте fenced code block с языком: `json`, `yaml`, `bash` или `http`.

```yaml
BOOKING_SERVICE_URL: http://localhost:8080
```

Не оставляйте блок кода без пояснения: перед ним укажите, где выполнить команду и что изменится после её запуска.

## Заголовки и списки

На странице используйте один заголовок первого уровня. Заголовок должен называть содержание раздела: «Настройка локального окружения» понятнее, чем «Дополнительно». Не пропускайте уровни: после `#` используйте `##`, затем `###`.

Если пункты списка являются законченными предложениями, завершайте каждый пункт точкой. Если это короткие фрагменты одной конструкции, точку не ставьте. Не используйте список из одного пункта: замените его обычным абзацем.

## Ссылки

Текст ссылки должен сообщать назначение страницы. Для внешней ссылки укажите, что откроется: документация, форма, репозиторий или спецификация.

| Неудачно | Корректно |
| --- | --- |
| «Нажмите [здесь](technical.md)» | «Откройте [правила описания API](technical.md)». |
| «[Подробнее](https://example.com)» | «Откройте [спецификацию OpenAPI сервиса](https://example.com)». |
| `GET /bookings` без контекста | `GET /api/v1/bookings` с описанием результата. |

## Элементы интерфейса

Названия кнопок, полей и разделов выделяйте полужирным начертанием и записывайте так, как они показаны в интерфейсе. Для пути по интерфейсу используйте стрелку `→`.

Пример: «Откройте **Бронирования** → **Создать бронирование**, выберите ресторан и нажмите **Подтвердить**».

Не объясняйте действие только расположением, цветом или иконкой. Вместо «нажмите зелёную кнопку справа» напишите название кнопки и результат действия.

## Таблицы

Используйте таблицу, когда читателю нужно сравнить однотипные значения: параметры, коды ошибок, переменные окружения или роли. Не используйте таблицу для длинного связного объяснения или последовательности шагов.

- Дайте каждому столбцу короткий и однозначный заголовок.
- В первой строке укажите единицы измерения, если они нужны: «Тайм-аут, с».
- В одной ячейке размещайте одно значение или короткое правило.
- Для широкой таблицы оставляйте только существенные столбцы, а подробности выносите в текст или отдельную страницу.

| Переменная | Обязательна | Пример | Назначение |
| --- | --- | --- | --- |
| `BOOKING_SERVICE_URL` | Да | `http://localhost:8080` | Адрес сервиса бронирований. |
| `REQUEST_TIMEOUT_MS` | Нет | `5000` | Ограничение времени запроса в миллисекундах. |

## Рисунки и скриншоты

Добавляйте рисунок только тогда, когда он поясняет действие, состояние интерфейса или результат, который трудно описать текстом. Перед рисунком объясните, что на нём нужно увидеть, а после него сделайте вывод или укажите следующий шаг.

- Обрезайте скриншот до нужной области и не размещайте на нём секреты, персональные данные и нерелевантные вкладки.
- Подписывайте рисунок под изображением: «Рисунок 1 — Создание бронирования в личном кабинете».
- Для информативного изображения указывайте alt-текст, передающий смысл, а не тип файла.
- Если в изображении есть текст, продублируйте важную информацию в основном тексте или таблице.

Корректный alt-текст: `Создание бронирования: выбор ресторана, времени и количества гостей`.

## Примечания и предупреждения

Примечание добавляет полезный контекст, а предупреждение ставьте перед действием с существенным последствием. В предупреждении укажите риск и безопасное действие.

!!! warning "Безопасность примеров"

    Не размещайте в документации рабочие пароли, токены и ключи доступа. Используйте маркеры, например `<access_token>`.
