# Участие в проекте

## Как предложить изменение

1. Создайте ветку от актуальной `main`.
2. Опишите проблему и укажите страницу или правило, которое нужно изменить.
3. Обновите правило и связанные примеры.
4. Запустите Markdown lint и строгую сборку MkDocs.
5. Создайте commit и отправьте ветку в GitHub.
6. Откройте Pull Request в `main` с целью изменения и результатами проверок.

## Conventional Commits

Сообщение коммита должно кратко описывать изменение в формате Conventional Commits. Для документации используйте `docs`, для исправления — `fix`, для проверки CI — `ci`.

Примеры:

```text
docs: add accessibility guidelines
docs: clarify API example
fix: correct broken link
ci: run documentation checks
```

## Процесс review

Рецензент проверяет точность правила, понятность формулировки, соответствие примеров и результаты автоматических проверок. Автор отвечает на замечания, вносит правки отдельным commit и повторяет проверки. Pull Request объединяется после одобрения и успешного CI.

## Локальная сборка

В PowerShell установите зависимости и запустите сайт:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m mkdocs serve
```

Перед отправкой изменений выполните:

```powershell
npx --yes markdownlint-cli@0.45.0 "**/*.md" "#site"
python -m mkdocs build --strict
```

## Как добавить новый раздел

1. Создайте Markdown-файл в `docs/`.
2. Сформулируйте проверяемые правила и добавьте примеры, если они нужны.
3. Добавьте страницу в `nav` файла `mkdocs.yml`.
4. Обновите ссылки на связанные страницы.
5. Запустите проверки.
6. Создайте commit с понятным сообщением.
